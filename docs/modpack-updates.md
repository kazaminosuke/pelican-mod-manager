# 既存サーバーのModpack更新

PR #2の `84f21de` と、同じツリーを持つ名義修正後の `fff3d31` を比較基点にしました。既存の通常ZIP導入は旧Modを追跡せず、専用Server Packの導入は同名の既存ファイルをスキップしていました。差分更新は現在のModpackを記録し、同じリリースを固定して再検証します。

## EggとMod Managerの役割

- **Modrinth・CurseForge**はローダーEggでMinecraftとローダーを準備し、Mod Managerが選択した配布物を一時配置して検証します。作成時の自動起動は無効です。PelicanがEggのインストール終了を返した後で、管理ジョブが起動JARまたは `unix_args.txt` と、そこから参照されるローダーを確認します。版を固定できるEgg変数が必要です。専用Server Packは子ZIPの `variables.txt` または `manifest.json` を優先し、ZIP展開時に重複と矛盾も確認します。
- **Technic**は公式配布物と専用Eggを固定できる版を専用Eggで導入します。専用スクリプトによる導入は差分更新の対象外です。
- **FTB**は対応する公開リリースを作成・更新できます。WizardでパックIDとリリースIDを固定し、Minecraft・ローダーを準備するEggを選びます。Mod ManagerがFTB公式APIのファイル一覧を取得し、クライアント専用ファイルを除いた公開ファイルをWingsに一時配置します。配置先、サイズ、配布元のハッシュ、最終配置のSHA-256を検証し、全件が確認できてから導入済みとして記録します。
- **ATLauncher**は版の閲覧に対応します。

### FTBの対象と確認手順

- 配布元のファイル一覧からMinecraft・ローダーの固定版を確認でき、公開HTTPS URL、サイズ、SHA-256・SHA-512・SHA-1のいずれかのハッシュがそろい、Mod Managerが管理できる場所に配置するリリースが対象です。FTBがJavaの版を指定する場合は、対応するJavaイメージも必要です。非公開パックや専用の起動処理・独自の配置先を要求するパックは対象外です。ファイル一覧は24 MiB、サーバー向けの管理対象は20,000ファイルまでです。起動JARや確認に必要なローダーファイルが不足する場合、起動前に停止します。
- 公式インストーラー v1.0.54 は `-pack` と `-version` で版を固定できます。`-just-files` は `-no-java` と `-skip-modloader` を設定しますが、ローダーの取得処理は残ります。`-validate` は開けないファイルを読み飛ばし、起動構成やローダーの完全性の証明には使えません。インストーラーが書き出す `.manifest.json` にはパックID・リリースID・ターゲット・ファイル一覧が含まれますが、必要な起動ファイルの存在は保証しません。公式FTB Eggはインストーラーの失敗後も後続の処理が成功すると終了コード0を返せます。そのため、固定版のファイル一覧を公式APIから読み、ローダーEggの終了後に起動ファイルを別途検証します。[FTBインストーラーのオプションと検証](https://github.com/FTBTeam/FTB-Server-Installer/blob/3b015c2c30cb64320c17d964ca83714ebe171da2/main.go) · [公式APIの利用箇所](https://github.com/FTBTeam/FTB-Server-Installer/blob/3b015c2c30cb64320c17d964ca83714ebe171da2/repos/ftb.go) · [Pelican公式FTB Egg](https://github.com/pelican-eggs/minecraft/blob/c6f2262eb351054d1be44d3f6a3a605ae163d682/java/ftb/egg-f-t-b-server.json)
- 作成後は通知の `Modpackの進捗を開く` で結果を確認してください。配置に失敗した場合は、表示された原因を解消し、サーバーを停止したままMod Managerで同じリリースを選び、差分プレビューを作り直せます。既存サーバーの更新は、現在のローダー・Minecraft・Javaが対象版に合い、同じ方法で起動を検証できる場合に対応します。専用FTB Eggで導入済みのパックの所有権は引き継ぎません。

## 操作

1. サーバーのMod Managerで現在のModpackとリリースを確認し、`Modpackのリリースを選択` から指定版のプレビューを作成します。インストールに使う配布物と起動環境が確認できる版を対象にします。既存のEggや起動変数との不一致、対応していない再インストール方式はプレビュー作成前に表示して停止します。
2. プレビューでModの追加・置換・削除数、保持、競合、保護対象、および一時配置に必要な判明済み容量を確認します。詳細表示は先頭100件です。別のModpackへ切り替える場合は、適用前に切り替えを明示的に確認します。
3. サーバーを停止し、プレビューからPelicanの完全バックアップを作成します。Wingsがサーバー内の `.pelicanignore` または `.pteroignore` を引き継がないよう、除外ルールを含まないコメントを送ります。プラグインは既存バックアップの削除や枠の上書きを要求しません。対象サーバーでこのプレビューから作成したバックアップが、除外なしで成功してから適用できます。バックアップは通常の保持ポリシーに従います。適用時にMod Managerが付けたロックは適用完了または復旧検証後に解除します。
4. 更新の適用を押します。更新成功後の起動は選択式で、起動権限を適用時にも確認します。途中失敗時はロールバックし、元の版を更新済みとして扱いません。承認済みの状態で再試行できる場合も、プレビューからの変更やバックアップの状態を照合します。

この経路はModrinthの `.mrpack`、通常のCurseForge ZIP、CurseForgeの専用Server Pack、FTBの公開リリースのファイル一覧に対応します。CurseForgeの必須手動JARは、公式ファイルの検証と補充待機を経て続行します。Egg内部で展開する専用インストーラー方式からの上書き更新は対象外です。

## 所有管理と復旧

- 新規導入と既存の差分適用で実際に設置したファイルのパス、SHA-256、配布元、ファイルIDを取得できる場合はそのID、配置したリリースをPanelデータベースに記録します。カタログのハッシュスキャンで認識しただけのModと、単体Modとして明示的に導入したファイルを区別します。
- 現在の内容のSHA-256が台帳と一致するファイルだけを置換でき、配布先から外れた管理対象Modは一致時にだけ除去します。台帳のないファイルの所有は推測しません。台帳のない既存サーバーでModが競合する場合は、バックアップを取得したうえで利用者が先に整理し、プレビューを作り直します。初回の台帳には、その回に実際に配置したものから記録します。
- `server.properties` の `level-name` とワールドの目印、許可ディレクトリ、シンボリックリンク、大小文字の衝突を確認します。サーバー設定、独自Mod、ワールド、プレイヤー・権限・BAN情報を保護します。変更されていない管理対象configは版に従って置き換え、変更済みconfigは保持して競合を表示します。削除された設定テンプレートは既存設定を保持します。更新やパック切り替えでは、配布対象から外れ、所有台帳と現物のハッシュが一致するKubeJSのサーバー用スクリプトやデータパックなども削除対象になります。対象ファイルが編集済みの場合は、競合を解消するまで適用を停止します。
- 変更が必要なファイルをWingsに一時配置して検証し、全件が準備できてから適用します。予期しない停止でロールバックを確認できない場合は更新をロックします。PelicanのBackupsで記録されたバックアップを復元した後、Mod Managerの `復元したファイルを検証` を押すと、対象パスが元の内容・存在状態に戻っていることを確認してからロックを解除します。
- プラグイン内のファイル操作は既存のサーバー単位の排他を使います。直接のSFTP操作や別経路の起動まで排他できないため、適用中は外部の編集や起動を避けてください。JAR検証はファイルの同一性を確認するもので、Minecraft互換性の実動作確認には別途起動が必要です。

## 初回実装時の比較計測

PHP 8.4、Wingsとファイル配布のインメモリ代替、約16 KiBのJARを使い、変更なしの更新を各3回測定した中央値です。旧版は既存の導入1回、新版はプレビューと適用の合計です。時間には実ネットワーク、キュー待ち、バックアップ時間を含みません。Wings呼び出し数はファイル操作、配布元への回数は依存JAR取得です。

| 形式・ファイル数 | 処理時間 ms 前 → 後 | Wings操作 前 → 後 | 一覧取得 前 → 後 | 依存配布元取得 前 → 後 | PHPメモリピーク MiB 前 → 後 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Modrinth 40 | 3.43 → 6.86 | 280 → 84 | 80 → 4 | 40 → 0 | 10.5 → 18.8 |
| Modrinth 1,500 | 2,087.84 → 112.66 | 10,500 → 3,004 | 3,000 → 4 | 1,500 → 0 | 16.2 → 25.2 |
| Server Pack 3,000 | 18.48 → 402.71 | 1 → 6,004 | 1 → 4 | 0 → 0 | 18.0 → 26.4 |

| 形式・ファイル数 | 一覧応答 MiB 前 → 後 | Wingsからの内容読み取り MiB 前 → 後 | 依存JAR取得 MiB 前 → 後 | パックZIP 1回分 MiB |
| --- | ---: | ---: | ---: | ---: |
| Modrinth 40 | 0.41 → 0.006 | 0.00015 → 1.26 | 0.63 → 0 | 0.0066 |
| Modrinth 1,500 | 568.78 → 0.23 | 0.0057 → 47.26 | 23.63 → 0 | 0.24 |
| Server Pack 3,000 | 0.23 → 0.46 | 0 → 94.52 | 0 → 0 | 47.56 |

変更なしのケースではWingsへのJARアップロードは前後とも0です。旧版はパックZIPを1回取得し、新版はプレビューと適用で各1回取得します。CurseForge Core API、実環境の通信時間、バックアップ転送量はこの計測に含みません。旧Server Packは既存ファイルを検査せずに残すため、比較上は速くなります。新版は内容を確認するコストが増え、変更されていないファイルの再配置を避けます。

一覧は計画のフェーズ内でディレクトリごとに共有します。実ファイルを変更する場合は適用前に読み直します。変更なしの場合は、適用時の確認後に3回目の一覧・ハッシュ取得を省略しました。1,500ファイルでこの最適化により、Wings操作は4,506回から3,004回に減りました。カタログの選択ラベル取得時の重複検索も削除しています。

## テスト済みの範囲

- SQLiteの実マイグレーション、永続ジョブ入口、モック配布API・Wings・バックアップサービスを通して、プレビューから適用まで検証しました。
- 各アーカイブ形式、手動JAR、復元検証、期限外・キャンセル・再試行、別パック確認、停止確認とバックアップ失敗、旧Mod削除・ユーザー変更保護を自動テストしています。
- 認証付きCurseForge Core API、実Panel＋実Wingsのバックアップ保存・復元の一連の操作、Minecraftの起動は今回未検証です。

## 独立レビュー後の比較計測

PHP 8.4.28、SQLiteとループバックHTTPで、約32 KiBのJARを10%置換、5%追加、5%削除する差分適用を各3回測定しました。比較元は `fa7fb51` です。配布APIとWingsの応答には試験用の代替サービスを使用しました。時間はローカルZIPの処理を開始してからで、実ネットワーク、Egg、バックアップの時間は含みません。

| 形式 | JAR数 | 適用時間 ms 前 → 後 | ファイルAPI 前 → 後 |
| --- | ---: | ---: | ---: |
| Modrinth | 40 | 70 → 78 | 136 → 125 |
| Modrinth | 1,000 | 1,767 → 1,559 | 3,208 → 2,910 |
| CurseForge 通常ZIP | 40 | 90 → 83 | 144 → 130 |
| CurseForge 通常ZIP | 1,000 | 1,936 → 1,734 | 3,408 → 3,011 |
| CurseForge 専用ZIP | 40 | 75 → 72 | 136 → 125 |
| CurseForge 専用ZIP | 1,000 | 1,788 → 1,627 | 3,208 → 2,910 |

1,000件の通常ZIPでは10%を手動補充済みとし、差分適用時のディレクトリ一覧を106回から7回、削除要求を300回から2回に削減しました。全ケースでファイル内容の読み取り量は同じです。プレビューで承認対象となった配布物はPanelの非公開キャッシュに1件64 MiB、合計256 MiBまで保持し、適用時にSHA-256を照合します。キャッシュがない場合は配布元から再取得して照合します。

標準Quilt Eggには固定ビルドの変数がなく、既知のビルドを要求するリリースには、対応する変数と検証できる起動ファイルを持つEggが必要です。実Panelと実Wingsのバックアップ復元、公式イメージでのMinecraft起動、認証付きCurseForgeは、この追試の範囲外です。

## FTBカタログとファイル一覧の計測

PHP 8.4.28で、ループバックHTTPの検索応答に20 ms、各パックの概要応答に60 msを加えました。パック6件の検索と、続けて先頭パックの版一覧を開く操作を各5回測定した中央値です。比較元は `c6d0260` です。概要は最大6件を並行取得し、同じ概要を60秒間再利用します。固定リリースのファイル一覧はこのキャッシュに含めません。

| 概要キャッシュ | 時間 ms 前 → 後 | HTTP要求数 前 → 後 |
| --- | ---: | ---: |
| なし | 469.5 → 93.8 | 8 → 7 |
| あり | 477.6 → 21.7 | 8 → 1 |

合成データのファイル一覧を検証し、固定内容の指紋を計算する処理は、40件で0.19 ms、1,000件で4.88 msでした。追加のPHPメモリピークはそれぞれ60 KiB、1.37 MiBです。各7回の中央値で、ファイル本体の取得、Wingsによる一時配置、サーバー起動は含みません。実際の配布ファイルに対するSHA-1とSHA-256の照合手順は共通の差分更新で実施します。

FTBの自動テストでは、公開API応答とWingsを代替し、SQLiteの台帳、Wizardからのジョブ登録、固定版の新規配置、ダウンロードの途中失敗と再試行、既存サーバーのプレビュー・バックアップ・適用を確認しました。公式イメージでの起動と公開パックごとの実ファイル到達性は、実Panelと実Wingsでの確認項目です。
