## 2. Logic Chain

1. **Outdated audits cannot be trusted as current ground truth** (Obs Pillar 1.B #1–#7): Four of the five docs contain materially stale claims (FTB 8 MiB / 2,000-file limits vs actual 24 MiB / 20,000; CurseForge Generic Egg fallback vs unified loader-Egg-only planner; unhashed Wings deploys vs full read-back hashing; missing `canEditEggProfile()` tests & Blade components vs implemented tests & JS assets). Planning must rely on `src/` at `4e5f839` and external specs.
2. **Multiple silent correctness bugs break real 2026 modpacks despite 729 passing unit tests** (Obs Pillar 1.D #1–#4, #7; Pillar 3.C):
   - Because `ModpackRuntime` had zero Fabric unit tests (Pillar 3.C) and Fabric 26.1+ dropped `intermediary` (Pillar 1.D #1), every MC 26.x Fabric modpack fails post-Egg runtime verification.
   - Because `ModpackCatalogTest`/`WizardTest` used tiny synthetic `.mrpack` fixtures and mocked `edge.forgecdn.net` with HTTP 206 (Pillar 3.C), two major real-world metadata-probing bugs went undetected: Modrinth `.mrpack` > 8 MiB drops pinned loader builds (Pillar 1.D #2) and `edge.forgecdn.net` 302 redirects break `CurseForgeManifestReader` (Pillar 1.D #3).
   - Because `FtbReleaseManifest` was tested on synthetic layouts without real FTB Inferno, `structurize/` aborts real FTB Inferno installs (Pillar 1.D #4).
   - Because `ServerEggMigration` has 0 unit tests and Pelican's `EggChangerService` preserves `skip_scripts` (Pillar 2.B, 3.C), migrating an existing server with `skip_scripts=true` silently skips loader installation.
3. **Deployment architecture has a fundamental throughput & Wings-compatibility bottleneck on real-world packs** (Obs Pillar 1.D #5–#6; Pillar 2.B):
   - Sequential per-file `pullForeground`/`putStream` + full `/files/contents` read-back + per-file `renameFiles` produces ~3N Wings HTTP requests (21k–48k for modern FTB packs) while holding the global 10-minute `withoutOverlapping(10)` scheduler lock, AND fails entirely when Wings disables remote downloads or sits behind a proxy.
   - Meanwhile, Wings natively supports unlimited-size authenticated streaming `/files/write` (with `Content-Length`, `ClearDeadlines`), disk-quota-checked `/files/decompress` (15m timeout), and batch `/files/rename` arrays (Pillar 2.B). Combining local/Panel-side verification + archive packing + `/files/write` + `/files/decompress` (or batching renames + eliminating redundant read-back after Panel-verified streaming + adding pre-send retry like `RetryingDaemonFileRepository`) directly solves both the 3N bottleneck and the Wings `disable_remote_download`/proxy limitation without weakening safety/ownership guarantees.
4. **CurseForge CDN URL reconstruction must NOT be adopted** (Obs Pillar 2.A #13, Live CDN probe): Reconstructing `edge.forgecdn.net` URLs when `downloadUrl` is `null` both violates CurseForge 3rd Party API Terms & Conditions (author `allowModDistribution` opt-out) and technically fails with HTTP `403 Forbidden` on modern files (verified live on ATM10 `9620/727`). Keeping `pelican-mod-manager`'s official-API + manual upload workflow is the right legal and technical posture, while fixing its real bugs (non-mod `classId` routing, pagination >30, `edge->mediafilez` allowlisted redirect in `CurseForgeManifestReader`, bulk chunk retry, `manifest_url` `$projectId`).
5. **Pelican Egg validation rules impose hard boundaries on what can be pinned automatically** (Obs Pillar 2.A #1–#4, #8): Any provisioning plan must validate generated variables against actual Egg rules (e.g., `NEOFORGE_VERSION` rejects `-beta`, `MC_VERSION` rejects >9 chars, Quilt Egg has no `QUILT_VERSION`, Forge Egg fails `unix_args.txt` on MC `26.x`).

## 4. Conclusion

The target plugin (`4e5f839`) already has a strong safety foundation (ownership ledger, diff preview, full-backup guard, crash recovery journal, CurseForge ToS-compliant manual upload workflow, Egg auto-detection, and 729 passing tests), **but independent verification against authoritative specs, official Pelican Eggs, Wings Go source, and live 2026 modpack APIs exposes concrete correctness bugs, scalability limits, outdated docs, and test blind spots that should drive Step 1 design priorities**:

1. **Fix Immediate Bootability & Metadata Bugs**:
   - Fix `ModpackRuntime.php` for unobfuscated **Minecraft 26.x Fabric** (no `intermediary` JAR) and read `serverJar=` from `fabric-server-launcher.properties` instead of hardcoding `minecraft-server.jar`.
   - Replace `ModpackCatalog::inspectModrinthArchive()`'s 8 MiB full download with bounded HTTP Range ZIP tail reading (handling 66–100+ MB `.mrpack` files cleanly) and generalize `CurseForgeManifestReader` to follow allowlisted HTTPS redirects (`edge.forgecdn.net` -> `mediafilez.forgecdn.net` and `cdn.modrinth.com`).
   - Add `structurize` (and review real FTB/CurseForge pack directories) to `ModpackPaths` / `FtbReleaseManifest`; support Modrinth `downloads[1..]` fallback mirrors and stream large overrides rather than capping at 2 MiB in PHP RAM.
   - Fix `ServerEggMigration::apply()` to explicitly reset `skip_scripts = false` before `ReinstallServerService`, use a sane daemon timeout (>1s), and add unit tests.
   - Validate Egg variable compatibility against actual Egg rules (e.g., NeoForge `-beta` builds vs `regex:/^[0-9\.\-]+$/`, `MC_VERSION` `max:9`, Forge MC `26.x` egg script gap).
   - Fix CurseForge modpack edge cases (`classId` destination routing for resourcepacks/shaders/datapacks, manual URL pattern, `listModpackVersions` pagination >30, `manifest_url` `$projectId`, bulk dependency chunk retries, and descriptive `User-Agent` header in `UpstreamHttp`).
2. **Eliminate the 3N Wings Round-Trip & `disable_remote_download` Bottlenecks**:
   - Add safe pre-send transport retries to `WingsRemoteFilesystem` (matching `RetryingDaemonFileRepository`'s pattern), enforce explicit `Content-Length` on `putStream`, batch `renameFiles` calls, avoid redundant Wings->Panel read-back when bytes were already hashed on Panel before streaming, and evaluate staging+uploading a single verified archive + Wings `/files/decompress` (plus Panel-assisted download fallback when Wings `/files/pull` is disabled/proxied) — dramatically cutting install time and avoiding the global 10-minute `withoutOverlapping(10)` scheduler lock stall.
3. **Evaluate Provider Scope Expansion Explicitly**:
   - **ATLauncher** is feasible to implement cleanly via `download.nodecdn.net/.../Configs.json` + `Configs.zip` (extracting exact loader+version, hashes, `server: true` filtering, `type: extract`, and pausing/blocking on `download: browser` or untrusted `direct` hosts), whereas **Technic** remains constrained for non-official packs unless Solder mod-ZIP overlay extraction + `bin/modpack.jar` loader detection is added.
4. **Upgrade Test Fidelity & Refresh `docs/*.md`**:
   - Close zero-coverage gaps (`ServerEggMigration`, `ModpackReviewArchive`, `InstallModpack`, `WingsRemoteFilesystem`, `ModpackRuntime` for Fabric 1.21/26.1 & Quilt).
   - Harden `DeploymentWings` to enforce real Wings semantics (`rename` refuses existing destination, `putStream` requires `Content-Length`, `pull` concurrency/disable modes) and add real-manifest / real-Egg-rules regression tests.
   - Update all 5 `docs/*.md` files to remove stale limits/claims (`8 MiB`/`2,000 files`, CurseForge Generic Egg, unhashed Wings deploys, missing `canEditEggProfile()` tests, removed Blade files).
